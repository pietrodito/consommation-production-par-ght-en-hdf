Consommation et production MCO par GHT en Hauts-de-France : l'outil de la PDH

Fiche de lecture proposée par le DIM du Centre Hospitalier de Dunkerque · 6 novembre 2026 · établie par lecture du code R, du modèle Power BI, des référentiels Excel et des CSV publiés dans les dépôts consommation-production-par-ght-en-hdf, atihdf et conso_prod_filieres, sans exécution sur la PDH

En bref

  • Outil destiné aux DIM de territoire, à exécuter dans la bulle de données de l'ATIH (Plateforme des Données Hospitalières : RStudio + Teradata)
  • Mesure, pour chacun des 14 GHT des Hauts-de-France, où les habitants sont hospitalisés (GHT de consommation = domicile du patient) et d'où viennent les patients des établissements (GHT de production = établissement), en MCO, par âge, type d'hospitalisation, CAS, groupe de planification et filière
  • Trois briques : le package R atihdf (boîte à outils PDH) → le projet R conso_prod_filieres (extraction, agrégation, CSV) → le modèle Power BI .pbit de ce dépôt (carte, matrice, segments)
  • Le dépôt consommation-production-par-ght-en-hdf contient le README, une capture et le modèle Power BI ; le code est dans les dépôts atihdf et conso_prod_filieres
  • Les résultats 2024 et 2025 déjà calculés sont publiés (conso_prod_filieres/out/, agrégés et masqués) : le rapport peut s'ouvrir sans accès à la PDH

3. À quoi ça sert

  • Taux de fuite d'un territoire : part des séjours des habitants d'un GHT réalisés hors de ce GHT, et vers quels GHT ou établissements
  • Attractivité : origine des patients d'un établissement ou d'un GHT, y compris les patients domiciliés hors région
  • Parts d'activité des établissements d'un territoire (publics et privés), pour une population donnée
  • Déclinaison par filière (définie par diagnostics), par groupe de planification ATIH, par âge (néonatologie, pédiatrie, adultes, plus de 75 ans), par mode HC / HDJ / séances
  • Comparaison 2024 / 2025 sur une même grille
  • Usages visés par le README : travaux des DIM de territoire (projet médical partagé, diagnostic territorial, échanges avec l'ARS)

4. Dépendances

Environnement PDH

  • Accès à la PDH ATIH (« bulle de données ATIH Data Expert » dans le README) avec RStudio et Teradata
  • pRatihque (package fourni par l'ATIH) : connexion LDAP, identifiant et mot de passe demandés à l'écran par teradata()
  • Droit de créer des tables temporaires Teradata (copy_to, compute)
  • Packages R attendus déjà installés : tidyverse (dplyr, tidyr, stringr, purrr, readr, tibble), dbplyr, DBI, readxl, glue, rlang, cli, rstudioapi, scales ; usethis et jsonlite pour reconstruire les données. Le fichier DESCRIPTION n'en déclare aucun (gabarit RStudio non rempli, seul magrittr)

Tables PDH lues

  • PRD_VUE_MCO_<année>.FIXE : RSA (ident, finess, codegeo, ghm2, dp, dr, duree, nbseance, age, agejour, typ_sej, mois…)
  • DIAG, UM, ACTE de la même base : connectées pour les futures filières, inutilisées aujourd'hui
  • PRD_VUE_NOMGEN.CORRESP_CODE_COM_GEO_TS_POP : code géographique PMSI ↔ communes, population
  • PRD_VUE_NOMPMSI.mco_rgp_ghm et mco_rgp_lib : GHM → ASO, CAS, GP, DA et libellés, par version de classification

Référentiels Excel (fournis)

  • ght_codegeo.xlsx, onglet COM_GHT : 3 818 communes → code GHT (14 GHT) ; un onglet COM_TAS (découpage TAS) n'est pas utilisé
  • raisons_sociales_juridiques_et_géographiques_GPS.xlsx : 961 FINESS des HDF (767 DGF, 194 OQN), raison sociale courte, coordonnées GPS et GHT ; seules les 330 lignes « Site principal » sont retenues (136 DGF, 194 OQN)

Power BI (poste)

5. Ce que fait le traitement R

lanceur.R boucle sur les années (annee_debut = 2024, annee_fin = 2025) et, pour chacune, exécute tous les scripts de R/ par ordre alphabétique avec la variable globale year. Une erreur dans un script est affichée sans arrêter la boucle.

7. Filières

Dans le code publié : une seule filière

  • 10-neurologie chronique.R : « Neuro. Chroni., Démences » = DP ou DR (3 premiers caractères) dans G10-G37, G60-G73 ou F00-F03
  • Le mécanisme : 00 écrit la table FIXE_FILIÈRES_PAIR, 01 la recopie en FIXE_FILIÈRES_IMPAIR, la filière lit IMPAIR et réécrit PAIR (rows_update par ident), 41 agrège PAIR
  • Ajouter une filière = un script de recopie PAIR → IMPAIR puis un script de filière, numérotés entre 10 et 41
  • Un séjour repéré par deux filières garde la dernière : pas de double compte, mais l'ordre des scripts compte

8. Secret statistique : le masquage

  • Une sortie de la PDH ne doit pas comporter de petits effectifs (moins de 11, règle ATIH)
  • Le script 41 contient une fonction de masquage, commentée dans le dépôt : chaque case de moins de S RSA (S cherché entre 11 et 30) devient aléatoirement 1 ou S, avec des probabilités qui conservent le total attendu (graine 2026). Le seuil retenu est le premier pour lequel lire « 1 » ou « S » renseigne moins sur un vrai 1 que l'affichage « <11 » de l'ATIH
  • Les CSV publiés sont masqués avec S = 12 : n vaut 1 (73 472 lignes en 2024, 50 267 en 2025) ou au moins 12, jamais 2 à 11
  • Le rapport affiche « <13 séjours » en dessous de 13 et une bulle de taille 1 sur la carte
  • Tel que publié, le script écrit les effectifs réels : réactiver le masquage avant toute sortie de la bulle. Conformité de cette méthode aux règles de sortie de l'ATIH : à confirmer (ce n'est pas une suppression des petites cases)
  • Conséquence : sur un total de GHT, l'aléa du masquage est estimé à 200 à 450 séjours (écart-type, moins de 0,4 %) ; une case fine (un établissement × un GP × une tranche d'âge) est approximative

11. Mode d'emploi

A. Lire les résultats publiés (sans PDH)

  1. Télécharger out/filières_GHT_2024.csv et _2025.csv du dépôt conso_prod_filieres dans un dossier dédié
  2. Ouvrir le .pbit dans Power BI Desktop, renseigner Dossier_data avec ce dossier
  3. Créer GHT.xlsx (feuille « Sheet 1 », colonnes CODE_GHT, GHT, finessJ_support) avec les 14 codes et libellés courts du § 10
  4. Créer hack_carte_rs_vides.xlsx avec les en-têtes du fichier GPS (contenu non publié ; vide à défaut), ou retirer l'étape « Hack » de la requête ES
  5. Repointer les 3 chemins U:\… (Transformer les données › Paramètres de la source de données), puis actualiser

B. Recalculer ou ajouter des filières (PDH)

  1. Zipper le dépôt atihdf, le téléverser dans RStudio de la PDH, Build › Install package
  2. Téléverser le projet conso_prod_filieres
  3. Vérifier le nom des bases MCO visibles avec son profil d'accès : le package vise PRD_VUE_MCO_<année>, un profil d'établissement peut ne voir que PRD_VUE_MCOBL_<année> (constaté au CH de Dunkerque en 09/2026). Le cas échéant, écrire ct(MCOBL, FIXE, DIAG, UM, ACTE, année = year) dans 00-conso-prod.R
  4. Ajuster les années dans lanceur.R, ajouter les scripts de filière (§ 7)
  5. Décommenter le masquage dans 41-aggrégation.R
  6. Lancer lanceur.R, récupérer out/*.csv selon les règles de sortie ATIH

13. Limites et points de vigilance

  • MCO seul : ni SMR, ni HAD, ni psychiatrie, ni ACE
  • Unité = RSA ; le rapport compte les séances une par une : séjours et séances s'additionnent dans « séjours »
  • « HDJ » = séjour sans nuitée, pas l'activité des unités d'hôpital de jour
  • Code géo → GHT par la commune la plus peuplée : un code géo à cheval sur deux GHT est rattaché en bloc
  • « Fuites » regroupe les établissements hors HDF et ceux des HDF absents des 330 sites principaux du référentiel
  • Le GHT de production est un territoire (cliniques comprises), pas le périmètre juridique du GHT
  • Effectifs masqués dans les CSV publiés : ordres de grandeur pour les cases fines
  • Script publié sans masquage actif : à corriger avant toute sortie de données
  • Filières : 1 définition publiée sur 13 utilisées ; un séjour n'appartient qu'à une filière, la dernière appliquée
  • CSV 2024 et 2025 produits par deux versions du script (traitement du FINESS hors région)
  • Nom des bases PRD_VUE_MCO_<année> à vérifier selon le profil d'accès PDH
  • Modèle Power BI dépendant de deux fichiers Excel non fournis et d'Azure Maps (accès réseau)
